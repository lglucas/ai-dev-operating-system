# 2026-08-09 — v0.5.4: o curso saiu de dentro do OS

**Versão:** v0.5.4
**Branch:** `chore/extract-course`
**Destino:** `lglucas/ai-dev-os-course` (privado)
**Anterior:** [v0.5.3 CODEMAP](2026-08-08-v0.5.3-codemap.md)

---

## Como a pergunta apareceu

Não foi tarefa planejada. O usuário perguntou, depois de eu explicar o PR #9:

> "Entendi, e está bem separado o curso do OS em si? Ou quando a pessoa clona o OS ela herda o curso junto?"

A resposta verificada foi **não**. `course/` estava rastreado na `main` (11 arquivos, 1.525 linhas), o `.gitignore` não o mencionava, o detach não o removia, e README, `START-HERE.md`, `CLAUDE.md` e `WIZARD.md` tinham **zero menções** à pasta.

Esse é o pior arranjo possível: presente no disco de todo projeto derivado, ausente de toda documentação. Quem clonasse para construir um SaaS encontraria uma pasta sobre um workshop que não comprou, sem nada explicando por quê.

Decisão do usuário: separar em repositório próprio.

---

## Por que as três justificativas originais caíram

O `course/README.md` registrava três razões para morar junto. Vale contrastar cada uma com o que de fato aconteceu, porque duas continuam válidas — só não dependiam de pasta compartilhada.

| Justificativa original | O que aconteceu |
|---|---|
| **Versionamento conjunto** — "se o OS muda, o curso muda junto" | Falso na prática. O OS foi da v0.4.5 à v0.5.3 e o curso não acompanhou nada: 66 referências a uma numeração de estágios extinta, em 20 arquivos. Mesmo repo, mesmas releases, envelhecimento solitário. |
| **Prova viva** — quem chega vê teoria e prática | Continua verdade, e um link entrega o mesmo. |
| **Open source consistente** | Não depende de fronteira de repositório. |

A primeira era a única que exigia coabitação, e é justamente a que os fatos desmentiram. **Acoplamento nominal não produz manutenção conjunta** — só a ilusão dela.

## O argumento que decidiu

Herança. E o detalhe que fecha o caso: o aviso "pode apagar esta pasta" existia **dentro da pasta** que a pessoa não sabia que tinha. Documentação que só é lida por quem já achou o problema não previne o problema.

Pior, a mitigação óbvia não funcionaria. Remover `course/` no script de detach cobriria só quem clona — e o caminho **recomendado** no README é o botão "Use this template", cujos usuários nunca rodam o detach, porque já nascem com origin próprio.

E a v0.5.3, de anteontem, tinha acabado de piorar o quadro: `course/systems/` contém `.js`, `.ts` e `.sql`, e o `SKIP_DIR` do gerador de codemap não cobria `course`. O `CODEMAP.md` de um fundador passaria a listar a infraestrutura do curso como se fosse código dele — no arquivo cuja função é achar o próprio código rápido.

---

## Como a migração foi feita

`git subtree split --prefix=course` nos dois pontos relevantes:

- da `main` → 11 arquivos, virou a `main` do repo novo;
- de `origin/sprint-0-systems-html` (o branch do PR #9) → 45 arquivos, virou branch homônimo lá.

Antes de remover qualquer coisa daqui, comparei as duas listas de arquivos com `diff`: **11/11 idênticos**. Só então o `git rm -r course/`.

No repo novo: `CHANGELOG-COURSE.md` → `CHANGELOG.md`, README reescrito de "descrição de subpasta" para "porta de entrada", `LICENSE` (MIT) e `.gitignore` adicionados. A licença não foi inventada — o próprio README do curso já declarava "mesma licença do AI Dev OS principal (MIT)", com atribuição CC-BY-SA 4.0 ao Experience Learning da Perestroika.

### O que ficou aqui, de propósito

`.claude/rules/wizard-stage-tags.md`. A convenção `[STAGE:X]` é opt-in e serve a qualquer um que queira rastrear progresso pelos commits. O curso é o maior consumidor, não o dono.

### Repo privado

Escolhi privado por ser o padrão reversível: privado→público é um clique, o contrário não desfaz indexação. Consequência imediata: **o README do OS cita o repo sem hyperlink**, porque um link para repositório privado devolve 404 ao lychee e derrubaria o CI. Quando virar público, é trocar por link.

## Um defeito meu, encontrado no caminho

`.claude-plugin/plugin.json` estava parado em `"version": "0.5.2"` e `"27 skills"` — uma release inteira atrás. Na v0.5.3 atualizei as contagens do README e **não propaguei** para o manifesto. Como nada consumia aqueles números, nada acusou.

A correção não foi só editar o arquivo. Virou o 10º grupo do `os-self-test`: confere que a versão do manifesto bate com o topo do `CHANGELOG.md` e que o número de skills anunciado bate com os `SKILL.md` existentes.

Estreou pegando o próprio commit que a criou — subi o manifesto para 0.5.4 antes de escrever a entrada do changelog, e o teste reprovou. Exatamente o comportamento desejado.
